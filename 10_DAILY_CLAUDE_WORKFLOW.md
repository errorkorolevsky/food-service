# FOOD SERVICE — DAILY CLAUDE WORKFLOW SYSTEM

## SYSTEM PURPOSE

Этот файл определяет:
- как Claude Code должен работать каждый день
- как запускать рабочий pipeline
- как выдавать задачи
- как контролировать качество
- как превратить Claude Code в полноценную AI product team

Главная цель:
создать стабильную ежедневную систему разработки проекта мирового уровня.


---

# GLOBAL DAILY WORKFLOW PHILOSOPHY

Claude Code НЕ должен работать:
- хаотично
- реактивно
- random-task style
- без контекста

Claude Code должен работать:
- системно
- product-oriented
- architecture-first
- UX-first
- roadmap-driven

## DAILY WORK MUST FEEL LIKE

- работа senior product team
- AI startup engineering workflow
- premium SaaS production pipeline


---

# DAILY WORKFLOW STRUCTURE

# EVERY SESSION MUST FOLLOW THIS FLOW

## STEP 1 — CONTEXT LOADING

Перед началом работы Claude Code обязан:

### READ:
- 01_PROJECT_CORE_CONTEXT.md
- 02_CLAUDE_CODE_OPERATING_SYSTEM.md
- 03_AGENT_TEAM_AND_SKILLS.md
- 04_UI_UX_MOTION_UPGRADE_PLAN.md
- 05_EXECUTION_ROADMAP_AND_TASKS.md
- 06_LOCALIZATION_RU_KZ_SYSTEM.md
- 07_CART_AND_CATALOG_RULES.md
- 08_DESIGN_REFERENCE_SYSTEM.md
- 09_QA_AND_SECURITY_RULES.md

## IMPORTANT

Claude Code обязан:
- работать только в рамках этих систем
- соблюдать architecture rules
- соблюдать design language
- соблюдать motion philosophy


---

# STEP 2 — PROJECT STATE ANALYSIS

Перед любыми изменениями Claude Code обязан:

## ANALYZE

### CURRENT PROJECT STATE
- current architecture
- current UI quality
- current responsive behavior
- current motion quality
- current performance

### CURRENT TASK STATE
- what already exists
- what already improved
- what remains unfinished
- possible risks

## IMPORTANT

Нельзя:
- начинать кодить без анализа


---

# STEP 3 — TASK IDENTIFICATION

Claude Code обязан определить:

## TASK TYPE

### P0 — CRITICAL
- runtime bugs
- hydration issues
- broken cart
- broken localization
- deployment issues

### P1 — HIGH
- mobile UX
- catalog UX
- cart UX
- homepage UX
- performance bottlenecks

### P2 — MEDIUM
- motion polish
- visual consistency
- spacing system
- microinteractions

### P3 — LOW
- experimental ideas
- advanced atmosphere systems
- future enhancements


---

# STEP 4 — PRE-IMPLEMENTATION ANALYSIS

Перед кодом Claude Code обязан написать:

# CURRENT STATE
Что существует сейчас.

# PROBLEMS
Какие проблемы обнаружены.

# STRATEGY
Как будет улучшено.

# IMPLEMENTATION PLAN
Какие шаги будут сделаны.

# EXPECTED RESULT
Как улучшится UX/UI/performance.


---

# STEP 5 — SAFE IMPLEMENTATION

## IMPLEMENTATION RULES

Изменения должны быть:
- modular
- isolated
- reversible
- readable
- scalable

## NEVER

- giant rewrites
- random refactors
- breaking architecture
- introducing chaos

## ALWAYS

- preserve consistency
- maintain scalability
- improve UX first


---

# STEP 6 — QA VALIDATION

После изменений Claude Code обязан проверить:

## FUNCTIONAL QA
- logic works?
- no runtime errors?
- no warnings?

## UI QA
- spacing consistent?
- typography balanced?
- hover polished?

## RESPONSIVE QA
- mobile works?
- tablet works?
- desktop works?

## MOTION QA
- smooth?
- optimized?
- cinematic?

## PERFORMANCE QA
- no rerender storms?
- no layout shifts?
- optimized animations?


---

# STEP 7 — FINAL POLISH

После working implementation Claude Code обязан:

## POLISH

### IMPROVE:
- spacing
- motion timing
- typography rhythm
- visual balance
- hover quality
- interaction smoothness

## IMPORTANT

UI никогда не должен:
- выглядеть unfinished
- ощущаться rough
- иметь inconsistent details


---

# STEP 8 — CHANGE SUMMARY

После завершения Claude Code обязан написать:

# WHAT WAS IMPROVED
Что было улучшено.

# WHY IT MATTERS
Как это улучшает UX/product.

# PERFORMANCE IMPACT
Как это влияет на performance.

# FUTURE IMPROVEMENTS
Что можно улучшить дальше.


---
